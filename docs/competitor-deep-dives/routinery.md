## Product architecture

Routinery treats a routine as an executable ordered flow rather than a passive
checklist:

- user-defined routine;
- ordered tasks;
- expected duration per task;
- start and guided step progression;
- countdown/elapsed timing;
- voice prompts;
- completion, skip and adaptation;
- watch/tablet support;
- short reflection after completion;
- consistency/history feedback.

## Visual and interaction grammar

- One current task receives primary focus.
- Remaining routine/time gives orientation without dominating.
- Timer continues the flow and reduces repeated decisions.
- Completion moves directly to the next step.
- End state supports reflection rather than only a streak reward.
- Routine builder separates configuration from execution.

## Product lessons, not widget decisions

- A due routine, an executing routine and historical consistency are different
  states.
- Any user-defined step must be possible.
- Timing can guide execution but cannot define whether personal care was
  performed correctly.
- Skipped, partial and interrupted routines need first-class records.
- Routine execution should connect with the planner without becoming a second
  planner.
